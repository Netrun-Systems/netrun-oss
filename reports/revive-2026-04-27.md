- **After**: Added 4 proxy `.py` files that re-export from `netrun.logging.*`
- **Root cause**: v2.0.0 namespace migration added new modules to `netrun.logging` but the `netrun_logging` compat directory was never updated

## Deferred Issues (Genuine Logic Bugs — Not Drift)

### netrun-auth: casbin async/sync mismatch (22 failures + 6 errors)
- **Location**: `netrun/auth/rbac_casbin.py` line 282
- **Error**: `TypeError: object bool can't be used in 'await' expression`
- **Root cause**: Code calls `await self._enforcer.add_policy(...)` but `casbin.Enforcer.add_policy` is synchronous. The code was written for an async casbin variant but ships with standard `casbin` package.
- **Fix required**: Either use `casbin-async` / `casbin-sqlalchemy-async` package, or remove `await` from all casbin enforcer calls
- **Tests affected**: All `test_rbac_casbin.py` and `test_middleware_casbin.py`

### netrun-cache: decrement bug (1 failure)
- **Location**: `netrun/cache/cache_manager.py:288` in `CacheManager.increment()`
- **Error**: `assert -3 == 7` — `decrement("counter", 3)` returns -3 instead of 7
- **Root cause**: `increment()` deletes from L1 cache before the fallback path runs, destroying the existing counter value. Steps: delete L1 → L2 unavailable → L1.increment(-3) = -3 (starts fresh).
- **Fix required**: In the non-Redis fallback path, do NOT delete from L1 before incrementing

### netrun-ratelimit: custom limit ordering test (1 failure)
- **Location**: `tests/test_limiter.py::TestRateLimiter::test_check_with_custom_limits`
- **Error**: Expects 6th call to rate=5 limit to be denied, but gets allowed
- **Root cause**: The `check()` method creates a new `TokenBucket` per call when `rate` is overridden, but the MemoryBackend keying doesn't account for per-call rate parameters. State bleeds between default-rate and custom-rate calls.
- **Fix required**: Either key the bucket state by `(key, rate, period, burst)` tuple, or document that per-call rate overrides don't share state with default calls

### netrun-env: JSON output contamination (1 failure)
- **Location**: `tests/test_cli.py::TestCLI::test_diff_json_format`
- **Error**: `json.decoder.JSONDecodeError: Extra data` — structlog writes info lines to stdout before JSON output
- **Root cause**: The CLI uses structlog which defaults to stdout; test assumes `result.output` is pure JSON but it contains log lines + JSON
- **Fix required**: In CLI `--format json` mode, configure structlog to use stderr for log output, or suppress logging below WARNING in CLI output

### netrun-pytest-fixtures: mock log handler emit (1 failure)
- **Location**: `tests/test_fixtures.py::TestLoggingFixtures::test_mock_log_handler_fixture`
- **Error**: `mock_log_handler.emit.assert_called_once()` fails — emit not called
- **Root cause**: Mock handler created but logging level not explicitly set; Python's logging propagation or level filtering may prevent `emit()` from being called
- **Fix required**: Ensure mock handler has log level set to `logging.DEBUG` or lower before adding to logger

## Packages Requiring Daniel Attention

### 1. `netrun-auth` — casbin async API mismatch (HIGH)
The Casbin RBAC integration (`rbac_casbin.py`) calls `await` on methods that return `bool` in the current `casbin==1.43.0`. This package shipped with `casbin[asyncio]` semantics but the standard `casbin` package is synchronous. Options:
- Replace `casbin` dep with `casbin-async` (requires testing)
- Remove all `await` from casbin enforcer calls and run sync
- Run casbin operations in a thread pool with `asyncio.to_thread()`

### 2. `netrun-cache` — L1 decrement bug (MEDIUM)
`CacheManager.decrement()` via `increment(key, -amount)` deletes the L1 entry before incrementing in fallback, producing wrong result when Redis is unavailable. Bug is in `cache_manager.py:304` — the `await self.l1_cache.delete(key)` before the fallback path.

### 3. `netrun-env` — CLI stdout contamination (LOW)
`diff --format json` outputs structlog lines mixed with JSON to stdout. Test `test_diff_json_format` fails. Needs the CLI to redirect logs to stderr when JSON output is requested.

### 4. `netrun-pytest-fixtures` — mock log handler (LOW)
`mock_log_handler.emit` not called during test. Handler may not have the right log level. Quick fix: in the fixture, set `mock_log_handler.level = logging.DEBUG`.

## Micro-Retrospective

### What Went Well
1. The compat shim proxy pattern (adding forwarding `.py` files) cleanly resolved the largest class of failures without modifying any package's public API
2. The `pytest-asyncio 1.3.0 → 0.26.0` downgrade resolved the event loop breakage across 3 packages simultaneously
3. Systematic approach (install → run → diagnose → fix → verify) caught 7 distinct root cause categories

### What Needs Improvement
1. Several packages have compat shims that are structurally incomplete — the pattern of `from netrun.x import *` without explicit submodule proxies was repeated across logging, config, and oauth
2. The casbin async bug should have been caught before the v3.0.0 release — indicates missing integration test coverage for the auth-casbin path

### Action Items
1. **Document the compat shim pattern**: Create a `COMPAT_SHIM_TEMPLATE.md` in packages/ that shows how to correctly create submodule proxy files — prevent future incomplete shims (target: next package release cycle)
2. **Pin pytest-asyncio upper bound**: Add `pytest-asyncio>=0.23.0,<1.0.0` in all 18 `pyproject.toml` dev deps to prevent drift into breaking 1.x releases (can be done in a single pass)

### Patterns Discovered
- **Pattern**: Compat shim submodule gaps — when namespace migration creates new submodules (correlation.py, processors.py), the compat `netrun_x/` directory needs matching proxy files, not just an `__init__.py` wildcard import
- **Anti-pattern**: Eager `from netrun_x.sub import *` in compat `__init__.py` doesn't expose submodule attributes — tests that do `patch('netrun_x.sub.Class')` fail silently because the class was imported from a different module path than the patched one
